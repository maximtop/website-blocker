4. Для нового сайта искусственно отказал первый remove: строка осталась, ошибка видима, кнопка снова доступна. Повторный Delete успешен, оба окна показывают пустой список.

## Совместимость и оставшиеся ограничения

- Новые записи перекрывают старую карту до фильтрации expiry. Поэтому `null` или истёкший override не может случайно вернуть legacy permanent блок. Проверены удаление, expiry, повторное добавление и сохранность посторонних данных.
- Старая карта не мигрируется массовой записью и не удаляется. Первоначальный QA-10 описывал очистку всей карты при Add; после B1 это поведение намеренно изменено: Add заменяет только запись своего hostname.
- Одновременные изменения **разных** сайтов сохраняются независимо. Для действительно одновременных изменений одного hostname остаётся обычная семантика последней записи browser storage; межустройственные транзакции не добавлялись.
- Старые версии расширения, понимающие только карту `websites`, не видят новые per-host записи. Для общего списка на нескольких устройствах нужны обновлённые клиенты. Совместимость чтения уже сохранённых старых данных сохранена.
- Истёкшие overrides остаются до повторного добавления/удаления того же hostname; tombstones для legacy сохраняются. Они расходуют лимит browser sync storage. Массовая очистка по устаревшему snapshot могла бы удалить новую запись другого контекста, поэтому безопасная сборка таких записей не включена в это исправление. Если storage отклоняет запись, ошибка сообщается и существующие данные сохраняются.
- Непройденные native сценарии из первоначального QA остаются непроверенными. Полный повторный прогон QA-плана не заявляется.

На момент этого прогона изменения были готовы к ревью; коммиты, публикация и отправка в магазин ещё не выполнялись.
